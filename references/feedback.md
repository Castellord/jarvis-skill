# Обучение на фидбеке

Точность Jarvis набирается здесь, а не в мастере настройки. Любая реплика
пользователя про конкретное письмо или задачу — это правило, которое нужно
сохранить, иначе завтра ошибка повторится.

## Грамматика

| Пользователь говорит | Что делать |
|---|---|
| «это шум», «больше не показывай», «отписаться бы» | правило шума, см. ниже |
| «это не задача», «не надо было заводить» | понизить до `important`, задачу удалить/закрыть, записать негативный пример |
| «это в проект X», «клади такое в Y» | `add-route` для категории |
| «это важно», «такое показывай всегда» | поднять до `important`, добавить отправителя в правило категории |
| «спрашивай меня перед созданием задач» | `jarvis.confirm_before_issue` = true |
| «не спрашивай, заводи сам» | `jarvis.confirm_before_issue` = false |
| «убери правило про X», «верни как было» | найти правило в routing-rules.yaml, удалить, подтвердить |

Фидбек может прийти и не сразу после разбора — «то письмо от банка было
шумом». Уточни, о каком письме речь, если непонятно, но не переспрашивай, если
контекст очевиден.

## «Это шум»

1. **Оцени, насколько чёткий паттерн.**
   - Чёткий — конкретный адрес или домен, который шлёт только такое. Идём в п.2.
   - Нечёткий — тема плавает, отправитель общий, совпадение только по словам.
     Сразу п.3, провайдерский фильтр тут навредит.
2. **Фильтр на стороне провайдера** (только если поддерживается, см. ниже):
   `mcp__emailmcp__email_filters` create с `criteria: {from: "<адрес/домен>"}`,
   `action: {add_label: "<префикс>Noise", skip_inbox: true, mark_read: true}`.
   Успех — запиши в аудит:
   `python3 scripts/jarvis.py harden --account <id> --from <addr> --filter-id <id>`.
3. **Правило в файле** (фолбэк и основной путь для нечётких паттернов):
   ```bash
   python3 scripts/jarvis.py add-noise --from-domain news.example.com --note "просил 21.08"
   python3 scripts/jarvis.py add-noise --subject-contains "дайджест" --note "…"
   ```
   Правило должно быть **ровно** таким узким, как сказал пользователь. Сказали
   про адрес — не обобщай до домена. Сказали про домен — не трогай соседние.

Всегда подтверди одной строкой, что именно сделано и как это отменить:
«Домен news.example.com больше не показываю. Скажи "верни news.example.com",
если передумаешь.»

## Поддержка фильтров по провайдерам

Перед первой попыткой на аккаунте просто вызови `email_filters` list и смотри
на ответ — таблицу поддержки не держи в голове, она устаревает.

| Провайдер | Ожидание |
|---|---|
| Gmail | фильтры доступны; лимит 1000 на аккаунт, при >900 предупреди пользователя |
| Yandex | публичного API пользовательских фильтров нет — сразу п.3, без попытки вызова |
| прочие | определяй по ответу list |

Ошибка `insufficient scope` / 403 на Gmail — скажи прямым текстом, что нужна
переавторизация через `mcp__emailmcp__email_connect_url` с добавлением
`gmail.settings.basic`, и временно примени фолбэк из п.3.

Никогда не создавай фильтр с широким доменом, накрывающим доверенных
отправителей (домен работодателя, банка), если просили про конкретный адрес.
Есть сомнение в охвате — переспроси одной строкой.

## Что можно потерять

Правило шума — единственный способ незаметно потерять важное письмо, поэтому:

- Раз в месяц при отчёте показывай одну строку: сколько писем отсеяли правила и
  сколькими правилами. Резкий рост — повод показать список.
- По просьбе «покажи правила» выводи содержимое `noise` и `routing` человеческим
  списком с пояснением, откуда взялось каждое правило (поле `note`).
- Любое правило должно сниматься одной фразой. Если пользователь не понимает,
  почему письмо пропало, — покажи сработавшее правило, а не общий совет.

## Ограничение записи

`scripts/jarvis.py` перезаписывает routing-rules.yaml канонически и **не
сохраняет комментарии пользователя**. Если пользователь правил файл руками и
оставлял пометки — предупреди об этом до первой автоматической записи.
