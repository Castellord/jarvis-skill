# Разбор писем: уровень 3 (LLM) и правила уровня 2

Уровень 2 считает `scripts/jarvis.py match` — сюда попадают только треды с
вердиктом `unresolved`.

## Категории

- **noise** — рассылки, no-reply уведомления, автодайджесты, маркетинг. Ничего
  не требует и ничего лично не сообщает.
- **important** — сообщает что-то значимое, но действия сейчас не требует:
  списание по карте, подтверждение брони, письмо знакомого без просьбы.
  Попадает в сводку.
- **actionable** — нужно конкретное действие в обозримом будущем: ответить,
  оплатить, подготовить документ, среагировать на срок, разобрать вложение.
  Заводится задача.

Ключевой вопрос для различения `important` и `actionable`: **что именно
пользователь должен сделать и когда?** Если на это нет ответа одной фразой с
глаголом — это не `actionable`.

## Формат вывода

Строго JSON, по одному объекту на тред, `rationale` первым полем — он
заставляет модель обосновать решение до того, как она его зафиксирует.

```json
{
  "thread_id": "…",
  "rationale": "Одно предложение: почему такое решение",
  "category": "noise|important|actionable",
  "confidence": 0.0,
  "category_key": "medical|home|finance|work|personal|null",
  "action_line": "Конкретное действие с глаголом — только для actionable",
  "summary_line": "Одна строка для сводки — для important"
}
```

`category_key` — это ключ секции `routing` в routing-rules.yaml. Передай его в
`scripts/jarvis.py match --category <key>`, чтобы получить team/project;
подстановку дефолтов скрипт сделает сам. Если пользователь заводит новую
категорию в одном месте — спроси, нужна ли она во втором.

## Батчинг

Классифицируй до 20 тредов одним вызовом, отдавая массив объектов. Один вызов
на письмо — основной источник стоимости прогона; при 50 письмах разница
существенная.

## Примеры

| Письмо | Решение |
|---|---|
| `noreply@service.com`, «Ваш еженедельный дайджест» | `noise`, 0.97 |
| УК, «Отключение электричества 22.08 с 10 до 14» | `actionable`, 0.9, `home`, «Решить, кто будет дома 22.08 с 10 до 14» |
| Клиника, «Результаты анализов готовы», PDF | `actionable`, 0.92, `medical`, «Забрать результаты анализов и внести в трекер» |
| Друг, «Го в выходные?» | `important`, 0.8, «Друг зовёт на выходных» |
| Банк, уведомление о списании | `important`, 0.85 |
| Хостинг, «Домен истекает через 7 дней» | `actionable`, 0.95, `work`, «Продлить домен до 28.08» |

## Границы

- `confidence < 0.6` → ставь `important`, а не `actionable`.
- Вложения на этом уровне не читай — только имя и тип файла. Разбор делает
  сабагент после того, как тред признан `actionable`.
- Письмо от живого человека лично пользователю почти никогда не `noise`, даже
  если выглядит как рассылка. Потерять такое дороже, чем показать лишнее.
- Не выводи `actionable` из одного лишь слова «срочно» в теме — маркетинг
  использует его постоянно. Смотри на отправителя.

## Структура routing-rules.yaml

Читает и пишет этот файл скрипт; правь руками только осознанно.

```yaml
version: 1
noise:
  - match: {from_domain: "news.example.com"}
  - match: {subject_contains: ["дайджест", "unsubscribe"]}
senders_hardened:              # фильтры, поднятые на сторону провайдера; только аудит
  - {account_id: "…", from: "…", filter_id: "…"}
routing:
  home:
    keywords: ["управляющая компания", "отключение"]
    from_domains: []
    team: "<TEAM_ID>"
    project: "<PROJECT_ID>"
    labels: []
    privacy: normal            # strict = не эскалировать в облачную LLM
defaults:                      # единственный источник правды для дефолтов
  team: "<TEAM_ID>"
  project: "<PROJECT_ID>"
```

Порядок проверки: сначала весь `noise`, затем `routing` (побеждает первое
совпадение). Совпадение — если сработало **любое** из `keywords`/`from_domains`.
Ничего не совпало — тред идёт на уровень 3.

Дефолтные team/project живут **только** здесь. В конфиге скилла их нет
намеренно: две точки правды рассинхронизируются.
